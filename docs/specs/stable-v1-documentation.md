# Stable-v1 documentation contract

**Status:** normative for the `1.0.0` release documentation.

## 1. Scope

The Supported Rust API recorded by `docs/specs/api-compatibility.md` and the Supported command-line
contract documented in `website/docs/reference/cli.md` are stable-v1 commitments. Current crate
documentation, the README and current website pages MUST describe them as frozen for compatible
evolution throughout major version 1. A breaking change to either Supported surface requires a new
major version; a changelog entry alone is not permission to break it.

Compatible additions remain possible where the contract reserves them, including
`#[non_exhaustive]` types, constructors, builders and defaulted trait methods. “Frozen” means that
existing downstream source and documented commands remain compatible, not that v1 can never gain a
new capability.

An item or subtree explicitly classified as Experimental remains outside the Supported
compatibility baseline. Current documentation MUST continue to say that Experimental roots may
change or be removed without migration guidance, including during the v1 line. Stable v1 MUST NOT
silently promote the language-neutral application contract, browser SDK, browser kernel or another
Experimental surface.

## 2. Current, generated and historical text

The current contract applies to crate-level and module-level Rust documentation, the CLI stability
header, the README, and non-historical website prose. Hand-maintained current installation examples
MUST use the exact `1.0.0` requirement.

Generated regions remain owned by `scripts/sync-website.py`; this story changes their source facts
or surrounding prose, never their generated bytes by hand. The same rule applies to the generated
comparison and compliance projections.

Past release sections under `website/docs/whats-new.md` are historical evidence and MUST retain the
version and stability policy that were true when each release shipped. Only the first release
section, when it is the current workspace version, is current prose for this rule.

## 3. Consistency guard

`scripts/sync-website.py` MUST reject legacy statements that sipx is pre-1.0, that Supported APIs
are unfrozen, that the current release is a prerelease or release candidate, or that a current
hand-maintained install still selects the last release candidate. The guard scans current public
entry points and Rust stability documentation but excludes generated regions and historical What's
New sections.

The guard also requires the principal README and website entry point to state both halves of the
contract: Supported surfaces are frozen for compatible v1 evolution, and Experimental surfaces
remain unfrozen.

## 4. Test vectors

| Vector | Input | Expected result |
|---|---|---|
| V1-DOC-1 | Current README says public APIs are not frozen | reject with the source and line |
| V1-DOC-2 | A crate stability section says sipx is pre-1.0 | reject with the source and line |
| V1-DOC-3 | Current top release prose names `1.0.0-rc.24` | reject |
| V1-DOC-4 | A historical What's New section names its actual prerelease | accept |
| V1-DOC-5 | A generated region contains bytes pending regeneration | leave to the generated-region and public-fact checks |
| V1-DOC-6 | Supported is frozen and Experimental remains unfrozen | accept |
