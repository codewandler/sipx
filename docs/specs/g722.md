# G.722 wideband audio

**Status:** normative · **Story:** M-44 · **Crates:** `sipx-audio`, `sipx-media`, `sipx-call`,
`sipx-cli` · **References:** ITU-T G.722 (09/2012), RFC 3551 §4.5.2 and §6, RFC 3264

## 1. Codec

G.722 is sub-band ADPCM at 64 kbit/s: a 24-tap quadrature-mirror filter pair splits 16 kHz audio
into two 8 kHz bands, the lower band is coded with a 6-bit adaptive quantizer and the higher band
with a 2-bit one, and each pair of input samples becomes one output octet — bits 5..0 the
lower-band code, bits 7..6 the higher-band code. The decoder mirrors the split; both directions
carry adaptive predictor and scale-factor state, so encode and decode are stateful streams rather
than pure functions of a frame.

The implementation is native Rust in `sipx-audio::g722`, written from the recommendation's
fixed-point specification: all arithmetic is the recommendation's saturating 16-bit and 32-bit
operator set, so the output is bit-exact against the official digital test sequences rather than
merely audible. The decoder's lower band supports the recommendation's three operating modes
(6, 5 and 4 bits); RTP carries mode 1 (64 kbit/s), which is what the session layer uses.

`Encoder` and `Decoder` own their state. Feeding a decoder mid-stream (after loss) is legal and
converges, which is a property of the adaptation G.722 was designed with; neither side ever
panics on any input byte sequence.

## 2. RTP carriage (RFC 3551 §4.5.2)

Payload type 9 is G.722's static assignment (RFC 3551 §6). **The RTP timestamp clock rate is
8,000 while the audio is sampled at 16 kHz** — §4.5.2 preserves this historical error
deliberately, and the rtpmap spelling stays `G722/8000`. The two rates MUST be kept apart:

| Quantity | Rate | 20 ms packet |
|---|---|---|
| audio samples handed to and from the application | 16,000 | 320 samples |
| payload octets on the wire | 8,000 per second | 160 octets |
| RTP timestamp advance | 8,000 | 160 units |
| RTCP jitter, arrival clock, telephone-event durations | 8,000 | — |

A session therefore distinguishes its **audio rate** (16 kHz — packet sizing, PCM conversion,
resampling, WAV headers, recording durations) from its **RTP clock** (8,000 — timestamps,
jitter arithmetic, RFC 4733 event durations). Every other codec sipx carries has the two rates
equal; G.722 is the case that proves the separation is real. Getting it wrong produces audio
that plays at half or double speed, and nothing else catches it.

## 3. Negotiation (RFC 3264)

- An offer of **bare payload type 9 with no `a=rtpmap` line** is accepted; the static number
  identifies the format (RFC 8866 §6.6 makes the rtpmap optional for static types, and a stack
  rejecting exactly this offer is the field-reported failure this exists to prevent).
- An offer carrying `a=rtpmap:9 G722/8000` is accepted identically, and a *dynamic* number
  mapped to `G722/8000` is matched by the rtpmap, not the number.
- An offer that remaps 9 to another encoding name is **not** taken on the number; the rtpmap is
  authoritative.
- G.722 enters an offer only when the application's codec selection names it; negotiation never
  settles outside the selected set.

**Preference order.** In every named selection that includes it, G.722 sits **below Opus and
above G.711**, and the rule is stated rather than implied: Opus is the better wideband codec
wherever both ends have it, and wideband G.722 beats narrowband G.711 wherever they do not. An
explicit application-ordered list is used exactly as given.

## 4. Reference verification (ITU-T G.722 Appendix II)

Round-trip testing cannot verify a codec — two mirrored defects round-trip perfectly. The
implementation is held to the recommendation's own digital test sequences, recovered from the
ITU archive the way the RFC 4475 corpus is recovered from the RFC editor:

- `scripts/import-g722-corpus.sh` fetches the official archive from `itu.int` and writes (or
  with `--check`, verifies) `crates/sipx-audio/corpus/g722/` — the 17 sequence files in the
  16-bit big-endian binary form.
- File words: bit 0 set marks a state reset; an input sample occupies bits 15..1 (shift right
  one to use); a code word carries the lower-band code in bits 13..8 and the higher-band code
  in bits 15..14; a reference output occupies bits 15..1 (decoder output shifted left one).
- **Encoder:** the sequences drive the band coders directly, QMF bypassed, the same word to
  both bands: `bt1c1.xmt` must produce `bt2r1.cod` and `bt1c2.xmt` must produce `bt2r2.cod`,
  bit-exactly.
- **Decoder:** `bt2r1.cod`, `bt2r2.cod` and `bt1d3.cod` are decoded in each of the three modes;
  the lower-band output must equal `bt3l⟨n⟩.rc⟨mode⟩` and the higher-band output `bt3h⟨n⟩.rc0`,
  bit-exactly.

The committed corpus is byte-for-byte what the archive publishes and is never hand-edited; the
import script's `--check` re-derives it.

## 5. Vectors

| ID | Vector | Expected |
|---|---|---|
| G722-1 | `bt1c1.xmt`, `bt1c2.xmt` through the band encoders | `bt2r1.cod`, `bt2r2.cod`, bit-exact |
| G722-2 | `bt2r1/2.cod`, `bt1d3.cod` through the band decoders, modes 1–3 | matching `.rc1/.rc2/.rc3` and `.rc0`, bit-exact |
| G722-3 | 320 samples of 16 kHz audio through `Encoder` | 160 payload octets |
| G722-4 | 160 payload octets through `Decoder` | 320 samples of 16 kHz audio |
| G722-5 | a 20 ms G.722 media packet | RTP timestamp advances by 160, not 320 |
| G722-6 | `m=audio … 9` with **no** `a=rtpmap` | negotiated as G.722 |
| G722-7 | `m=audio … 9` + `a=rtpmap:9 G722/8000` | negotiated as G.722 |
| G722-8 | `a=rtpmap:9 iLBC/8000`-style remap | not taken on the number |
