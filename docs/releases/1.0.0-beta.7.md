# sipx 1.0.0-beta.7

sipx `1.0.0-beta.7` is a routing-integration prerelease. It gives forwarding consumers exact
operations over outgoing INVITE transactions, listener selection, identity fields and parser-owned
URI spans instead of requiring them to rebuild protocol state or edit wire bytes themselves.

Pin the exact Rust crates while the API remains pre-1.0:

```bash
cargo add sipx-call@=1.0.0-beta.7
```

Install the diagnostic phone from crates.io:

```bash
cargo install sipx-cli \
  --registry crates-io \
  --version '=1.0.0-beta.7' \
  --locked
```

The named browser-audio profile remains optional and needs both native media features:

```bash
cargo install sipx-cli \
  --registry crates-io \
  --version '=1.0.0-beta.7' \
  --locked \
  --features opus,dtls
```

## What changed since beta.6

- **A forwarding element can cancel one exact outgoing INVITE transaction.**
  `sipx_transport::Handle::cancel_invite` is anchored to the `Responses` value returned for the
  original transaction. It owns RFC 3261 CANCEL construction, waits for a provisional response,
  handles a final response winning the race, preserves events observed while waiting, and returns
  distinct INVITE and CANCEL terminal outcomes. The call layer now uses the same operation, leaving
  one construction path in the workspace.
- **Cleartext listener selection is exact.** `sipx_transport::Config` can select UDP only, TCP only,
  both on the same address and port, or no cleartext listener when another signalling listener is
  configured. TCP-only no longer opens a placeholder UDP socket, and invalid listener combinations
  fail before binding.
- **SIP identity and privacy fields have typed APIs.** Privacy values receive checked construction
  and message-wide validation. Asserted and preferred identity lists separate strict sending from
  tolerant receive filtering, with indexed diagnostics for malformed values rather than silent
  loss or whole-field rejection.
- **URI rewriting is parser-owned and lossless.** Applications can replace SIP or SIPS users, TEL
  subscribers, Request-URIs and URIs nested in typed address fields, or remove one flattened
  address-list value. Unchanged wire bytes remain exact. Parser hardening also validates generic
  percent escapes and TEL subscribers and applies the name-address boundary consistently.

## Migration and stability

Cleartext endpoint configuration has one intentional pre-1.0 breaking change. Replace the former
boolean TCP switch with an exact selection:

```rust
use sipx_transport::{CleartextTransports, Config};

let mut config = Config::default();
config.cleartext = CleartextTransports::UdpAndTcp;
```

Choose `Udp`, `Tcp`, `UdpAndTcp`, or `None` according to the listeners the host is actually allowed
to expose. The default remains UDP and TCP together. The cancellation, identity, privacy and URI
editing APIs are additive.

Public APIs are not frozen before stable 1.0. Supported APIs may still change with changelog and
migration guidance; Experimental APIs may change or be removed without that guide.

## Intentional limits

- **Transaction scope:** the new cancellation operation controls one existing outgoing INVITE
  client transaction. It does not choose proxy branches, implement Timer C policy or turn the
  endpoint library into a proxy product.
- **Identity policy:** typed privacy and asserted-identity fields expose protocol syntax and
  diagnostics. Trust-domain decisions, anonymisation and routing authorization remain application
  policy.
- **URI policy:** the editing seams validate and preserve syntax; they do not normalise telephone
  numbers, resolve routes or infer address ownership.
- **Comparative load scope:** beta.7 retains the checked current-endpoint dataset and does not add a
  peer result. Secure transports, connection churn, media, other call rates and an overall winner
  remain unmeasured.
- **Browser SDK status:** the contract remains normative, but the package, WebAssembly kernel
  adapter, browser signalling adapter and runnable application remain backlog.
- **Product roles:** proxy, registrar, PBX, routing-product and dial-plan roles remain outside this
  endpoint library.
- **Stable compatibility:** `1.0.0-beta.7` is a prerelease, not an API freeze.

Every public package is produced from one immutable annotated tag, verified from exact registry
versions, exercised through an installed Opus CLI, and checked against documentation deployed from
the same commit. This repository prerelease is not a broader announcement.
