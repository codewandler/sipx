# sipx 1.0.0-rc.21

This is the first public candidate after rc.17. The rc.18 and rc.19 boundaries were prepared but
never published. The rc.20 tag then reached its protected runner and stopped before package
publication because that runner lacked three tools required by the complete gate. This fresh
immutable boundary carries the same five-story conformance wave with the runner provisioning held
by failing-first release-workflow tests.

Stable promotion remains deliberately out of scope. It still requires use by an application nobody
in this repository wrote.

## Install

```sh
cargo add sipx-call@=1.0.0-rc.21
cargo install --locked --version '=1.0.0-rc.21' sipx-cli
```

## Release boundary

The protected release workflow now supplies every external tool used by its complete local gate:
the non-Linux cross compiler and Rust target, both WebAssembly targets, and the runtime that executes
the kernel proof. The ordinary CI jobs already installed those prerequisites separately; the
release job reunites their configurations and now reunites their setup as well. Structural mutation
tests remove each tool in turn and require the repository checker to refuse the workflow.

This follows the earlier dispatch repair in the same story. Gate timing evidence is derived only
after a runner exists, uses one runner-temporary file, and is checked at the expression-context
boundary that prevented rc.19 from creating a job.

## Five-story conformance wave

- Plan-side DSP validation returns a typed `FrameSamplesOutOfRange` before preparing a graph,
  allocating buffers or spawning a supervised worker. The worker retains its independent bound.
- The load-summary join test deterministically manufactures its real local-port collision, retries
  setup within the existing event bound and keeps setup contention distinct from a call outcome.
- The public privacy and logging guides state the redaction guarantee enforced in source: raw
  samples, encoded relay bytes, at-rest call bytes and fixed-size key material remain out of record
  diagnostics, while protocol headers, counts and lengths stay available for diagnosis.
- The architecture guide locates the sans-I/O processor contract and live graph in their owning
  crates, distinguishes Rust-supplied processors from the narrower process door, and assigns
  containment to execution profiles.
- The release workflow is dispatchable, provisions the full gate, and binds publication to one
  reviewed annotated tag, exact-SHA CI and Pages evidence, registry-consumer proof, portable
  artifacts and a prerelease record.

## Other carried hardening

This candidate also carries the application-controlled DSP graph, bounded supervised-worker
protocol, diagnostic redaction fixes, live-stage bypass and restore, renegotiation correction,
complete transition journalling, disappearing-leg events and the operator-controlled first-NOTIFY
deadline prepared at the rc.18 and rc.19 boundaries.

## Known and not fixed

The worker-protocol fuzzing vocabulary remains public API of a published crate. Its oracle must
drive the real crate-private callers, but its vocabulary can move to the test crate while one opaque
entry point stays behind. That refactor is recorded as `M-129` rather than rushed into this
candidate.
