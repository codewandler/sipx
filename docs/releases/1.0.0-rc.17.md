# sipx 1.0.0-rc.17

Five stories, finishing three things that had been true on paper and not in fact. A prerelease on
the same terms as its predecessors: stable promotion still requires use by an application nobody in
this repository wrote.

## Install

```sh
cargo add sipx-call@=1.0.0-rc.17
cargo install --locked --version '=1.0.0-rc.17' sipx-cli
```

## Fixed

**Nine types stopped rendering call audio in a `Debug` record.** `PcmFrame`, `PcmSamples`, `Wav`,
the DSP frame, scratch and sink, the stutter delay line, the G.722 codecs and `Encoded` all printed
their samples, so any tracing field, panic message or test failure carrying one put audio into a
record whose length was the buffer's. Each now reports identity and a sample count in a record
bounded independently of the audio, and `check-audio-claims.py` holds every published crate to it.
Encoded audio in `Bytes` is outside what an element type can decide — the same bytes are equally a
Call-ID or a SIP body — so the checker says that rather than implying coverage it does not have.

**A processor's heap is measured against what it declares.** `DSP-K9` reported the heap half
`Unproven` because `unsafe_code = "forbid"` covers every target of every workspace member and a
counting allocator does not merely violate a convention here — it does not compile. The measurement
now lives outside the workspace, on the same terms `wasm/` and `fuzz/` already use, and it is a gate
step, because a measurement nobody runs decays into a claim. `sipx.stutter`'s delay line is the
first declared heap figure ever checked, and it is exact to the byte.

**A row named as driver-composed must point at the thing that composes it.** The contract's
reachability table asserted only that a row was *absent* from the bridge — which a row nothing
produced anywhere satisfied perfectly. That asymmetry is why three separate stories each found one
specified-but-unreachable event; the table now checks composition, and the two rows that happened to
have real producers were verified for the first time.

## Added

**A supervised DSP stage runs its worker in an operating-system process** this crate spawns, kills
and reaps, so `SupervisedIsolated`'s containment claim is the one the specification writes rather
than a thread's approximation of it. It was done with no new dependency — a `[[bin]]` target and
`std::process::Command` — and the cost is stated rather than buried: **a published package now ships
an executable**, `sipx-dsp-worker`, whose command line becomes a compatibility surface.

**A host can perform the contract's `dial` verb**, and `call.dial.finished` reports how it resolved.
No host could emit it before, because the call layer never put a dial's outcome on an event at all.

**Interchangeable call-DSP noise reduction** — a `NoiseReducer` trait, a deterministic three-band
suppressor behind it, and a registry entry to attach it to a call. What it removes, what it damages,
and the five conditions under which it makes speech **worse than leaving it alone** are stated
normatively.

## Migration

- `sipx_media::dsp` is **Experimental** and changed: `with_supervised` takes a `WorkerProcess`, and
  `SupervisedWorker::run` takes a `DspFrame`.

## Intentional limits

- **No measured CPU, memory or quality figures** for the effects or the noise reducer; `X-109` owns
  that, and `M-66` left the rows depending on it unticked rather than inventing numbers.
- **No SDK surface for controlling a graph** (`M-67`), and nothing in the workspace sets the
  activity hint the reducer declares it consumes (`M-114`).
- **`sipx_rtp::Packet`, `Rtcp` and `SdesItem` still render their payloads** — the other end of the
  same relay path, filed as `M-110`. `SdesItem`'s bytes are a CNAME: personal data rather than audio.
- **No speech implementation ships** behind its contract.
- **AEAD interoperation is proven for `AEAD_AES_256_GCM` over DTLS only.**
- **The browser binding has no run against a real WSS endpoint.**
- **No independent production application or third-party security audit is recorded.**

## Evidence

- `./scripts/gate.py` reported **51 steps, all green** on the release commit.
- The new heap step was proved to fail before it was trusted: quartering `sipx.stutter`'s
  declaration fails all three delay lines, naming the arithmetic.
