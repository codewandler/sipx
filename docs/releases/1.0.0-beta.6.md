# sipx 1.0.0-beta.6

sipx `1.0.0-beta.6` is a signalling-responder correctness and specification prerelease. It hardens
the bounded endpoint measurement path, corrects validated-response accounting, and makes the next
browser, media and application boundaries explicit without presenting planned work as implemented.

Pin the exact Rust crates while the API remains pre-1.0:

```bash
cargo add sipx-call@=1.0.0-beta.6
```

Install the diagnostic phone from crates.io:

```bash
cargo install sipx-cli \
  --registry crates-io \
  --version '=1.0.0-beta.6' \
  --locked
```

The named browser-audio profile remains optional and needs both native media features:

```bash
cargo install sipx-cli \
  --registry crates-io \
  --version '=1.0.0-beta.6' \
  --locked \
  --features opus,dtls
```

## What changed since beta.5

- **The endpoint responder keeps its finite contract under load with less hot-path contention.**
  Dead-route cleanup is amortized; UDP intake uses a bounded batch and queue; completion processing
  remains fair; timer entries carry exact generations; invalid event capacity is refused as a
  typed configuration error; and a valid BYE arriving before ACK closes the early dialog without
  leaving state behind.
- **Response qualification now counts only protocol-valid responses.** Malformed responses can no
  longer contribute to the successful response total used by qualification and headroom evidence.
  The retained dataset publishes the current endpoint direction only. The peer direction remains
  explicitly unmeasured, so this release makes no new comparative winner claim and does not rerun
  or reinterpret the recorded measurements.
- **The browser SDK boundary is specified before implementation.** A normative contract fixes the
  browser-owned WebSocket, timer, entropy, certificate and WebRTC seams; bounded ABI and lifecycle;
  registration and call states; and byte-level refusal vectors. The SDK package, browser transport
  adapter and runnable demo remain future work.
- **Later media and application ideas are now bounded plans.** Local speech, call-audio analysis,
  custom DSP and realtime phone actions are split into design records and stories with explicit
  ownership, resource, privacy and evidence constraints. None is claimed as a beta.6 runtime
  capability.
- **Contributor and adoption guidance is clearer.** Repository workflow and public entry points
  identify the authoritative specifications and generated records more directly without changing
  existing application behavior.

## Migration and stability

The runtime changes are internal hardening of bounded responder and measurement paths. Existing
Supported call, transport, media and application APIs retain their beta.5 behavior. The browser SDK
specification and new planning records do not add public packages or runtime APIs, so no migration
is required for them.

Public APIs are not frozen before stable 1.0. Supported APIs may still change with changelog and
migration guidance; Experimental APIs may change or be removed without that guide.

## Intentional limits

- **Comparative load scope:** beta.6 retains the checked current-endpoint dataset and does not add a
  peer result. Secure transports, connection churn, media, other call rates and an overall winner
  remain unmeasured.
- **Browser SDK status:** the contract is normative, but the package, WebAssembly kernel adapter,
  browser signalling adapter and runnable application remain backlog.
- **Planned media/application work:** local speech, call-audio analysis, custom DSP and realtime
  phone-action records define future work; they are not shipped capabilities.
- **Realtime live-endpoint proof:** the deterministic bridge remains implemented, while its opt-in
  credentialed live-service proof has not yet been recorded.
- **Product roles:** proxy, registrar, PBX, routing-product and dial-plan roles remain outside this
  endpoint library.
- **Stable compatibility:** `1.0.0-beta.6` is a prerelease, not an API freeze.

Every public package is produced from one immutable annotated tag, verified from exact registry
versions, exercised through an installed Opus CLI, and checked against documentation deployed from
the same commit. This repository prerelease is not a broader announcement.
