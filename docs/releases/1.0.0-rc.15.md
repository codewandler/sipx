# sipx 1.0.0-rc.15

Five stories, four of them things that existed on paper and could not be reached in practice — plus
the first measurement of what media actually costs. A prerelease on the same terms as its
predecessors: stable promotion still requires use by an application nobody in this repository wrote.

## Install

```sh
cargo add sipx-call@=1.0.0-rc.15
cargo install --locked --version '=1.0.0-rc.15' sipx-cli
```

## Measured: what media costs

At **1000 concurrent calls** on an idle 20-core box, holding every call up for the whole run:

| | RSS | per call | setup p50 | drift |
|---|---|---|---|---|
| no media negotiated | 51 MB | 52 KB | 17.5 ms | 0.07 s |
| session bound, no audio | 119 MB | 121 KB | 36.5 ms | 0.73 s |
| audio flowing both ways | 218 MB | 223 KB | 34.7 ms | 0.74 s |

**Media costs about four times the memory of plain signalling, and most of the first doubling is the
stack rather than the audio.** Negotiating a session and binding a socket takes 51 MB to 119 MB
before a packet is sent; carrying audio then takes it to 218 MB. Drift says it more sharply — the
media-free run is an order of magnitude steadier, while audio on top of an already-negotiated
session adds essentially nothing. A deployment running media elsewhere is not saving a fraction; it
is working at roughly a quarter of the footprint.

`--media none` on `capacity_test` and `load_test` is what makes that measurable, and the caller half
it needs is now public in `sipx-call` and shared with `sipx load --mode signalling`.

**This is not deployment sizing.** Both ends share one process and one scheduler. Neither run found a
ceiling at 1000 calls; `docs/measurements/README.md` states what the figures do and do not support.

## Fixed

**`call.signal.metrics` and `call.signal.silence` can be emitted at last.** Both were specified,
typed and round-tripped over the wire, and no host could produce either: the bridge had no arm for
them, and no tests at all. Every `CallEvent` variant now either has a producing arm or is named with
the reason it has none, and a specified event with no producing arm is a red build.

**A call the far end cancelled is reported to an application as `remote`, not `error`.** An
invitation the peer withdrew is not the host failing to go on, and `sipx-call`'s own documentation
already said so. This changes what an application sees for a cancelled invitation.

**`sipx load` reports how far a candidate pass got** when a response deadline ended it. It had been
printing `candidates_attempted: null` for runs that walked the whole list, because that ending
carried no depth at all — the count was destroyed a layer below where it was read. `dial`, `peers`
and `scenario` gain the same pair on that ending.

**Two repository checkers stopped accepting what they could not see**: the extensibility guard reads
`#[non_exhaustive]` as an attribute rather than as a substring of the prose above a type, and the
versioned-contract table is read through the same row reader as the flag table.

## Added

**A bounded DSP graph can be attached to a live call**, per direction, validated whole before it
activates and replaced atomically at a sample boundary. Queue, frame, scratch, tail and processor
limits are explicit and non-zero; a failed stage bypasses open or tears the graph down as its policy
states, without awaiting or stalling RTP; teardown waits on a barrier proving no task, frame or
state is held.

A graph claims that over-budget work cannot stall RTP **only when every stage is proven-inline or
supervised-isolated**. One trusted-cooperative-native stage and the whole chain claims nothing,
because that stage is application code the media worker cannot preempt, cancel or reap.

## Intentional limits

- **The supervised DSP worker runs in a thread, not its own process** (`M-102`), so the isolation it
  names is not yet the isolation it provides. Stated in the crate's stability notes and the spec.
- **No DSP processor implementation ships.** The graph exists; the workspace registry is empty until
  `M-65`.
- **No speech implementation ships** behind its contract.
- **AEAD interoperation is proven for `AEAD_AES_256_GCM` over DTLS only.**
- **The browser binding has no run against a real WSS endpoint.**
- sipx is a programmable user-agent stack and diagnostic phone — not a proxy, registrar, PBX or
  general browser-media engine. Video is not admitted.
- **No independent production application or third-party security audit is recorded.**
