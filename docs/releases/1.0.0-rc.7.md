# sipx 1.0.0-rc.7

sipx `1.0.0-rc.7` fixes the added-delay behaviour two field reports described, and repairs three of
this project's own checks that were reporting less than they claimed. It is the sixth published
release candidate for stable 1.0 and remains a prerelease on the same terms as its predecessors:
Supported APIs receive migration guidance when they change, Experimental APIs may change without it,
and stable promotion still requires use by an application nobody in this repository wrote.

The candidates between `1.0.0-rc.2` and this one — `rc.3` through `rc.6` — were cut and verified
locally but never published. Their work is contained in this release; their tags are not on the
remote and no package was ever published from them.

## Install

Pin every sipx crate to the same exact release candidate:

```sh
cargo add sipx-call@=1.0.0-rc.7
```

Install the diagnostic CLI:

```sh
cargo install --locked \
  --version '=1.0.0-rc.7' \
  sipx-cli
```

For the browser-compatible audio path, add the optional native features:

```sh
cargo install --locked \
  --version '=1.0.0-rc.7' \
  --features opus,dtls \
  sipx-cli
```

The GitHub Release also carries native archives for x86-64 and Arm64 musl Linux, Intel and Arm64
macOS, and x86-64 Windows. Verify the selected archive against `SHA256SUMS`; its adjacent SPDX 2.3
document and internal `build-manifest.json` bind the dependency set, target, release commit,
toolchain and feature selection. Portable archives contain no optional native features.

## What changed after 1.0.0-rc.2

**Inbound audio is bounded in time.** The queue between a call and the application held 256 frames —
5.12 seconds at 20 ms packets — with no time bound, no counter and no shed policy. An application
reading slightly slower than real time settled at the far end of it and stayed there. It now holds a
stated duration, 200 ms by default, measured as queued audio rather than a frame count so the bound
means the same thing whatever packetisation the far end sends. Overflow sheds the oldest audio and
every shed frame is counted. The jitter buffer, which the original reports pointed at, was measured
across ten 1,500-packet traces and found sound.

**Calls report voice activity and signal metrics as typed events.** Both are deterministic signal
analysis over one bounded PCM seam — no speech model is loaded — carrying direction, call identity,
an observation sequence and sample time. Delivery cannot delay RTP; a slow consumer sees a sequence
gap rather than a stalled call. A frame the analyser refuses restarts the epoch rather than
vanishing, so a transition spanning the gap is reported.

**The signalling kernel runs in WebAssembly.** The sans-I/O SIP and SDP core builds without sockets,
an async runtime, a filesystem, an OS clock or an entropy source; the host supplies bytes, fired
timers, monotonic time and entropy across a versioned ABI. Native and wasm32 produce byte-identical
wire output, pinned by a digest over the full RFC 4475 and RFC 5118 replay. That replay caught a
torture case which had poisoned the kernel — in WebAssembly a panic is a trap, so it was one
malformed datagram from ending a page's endpoint.

**Media negotiates the RFC 7714 AEAD-GCM protection profiles**, offered strongest-first over SDES
and DTLS, selected by strength rather than by the order a peer listed them, with the counter-mode
profile remaining the floor. The DTLS profile names now come from the IANA registry rather than
OpenSSL's spelling.

**Every outbound command's stated deadline bounds target resolution**, `register` gained a
completion deadline it never had, and every `register` exit now joins its endpoint before reporting.
A connection failure says how many resolved addresses were tried alongside how many were resolved.

**Two dialogs can be coupled without touching their media** — the RFC 7092 §3.1.3 role drives both
dialogs and maps SDP transparently while binding no RTP and advertising no address of its own.

**Interchangeable local speech providers have an executable contract**: registry, discovery
descriptor, selection precedence with typed refusals, session lifecycle, an asynchronous driver, and
privacy admission with no retention by default.

## Migration and stability

- **`register` now defaults to a 20-second completion deadline** where it previously had none. A
  registrar that legitimately takes longer will fail where it previously succeeded; `--timeout 0`
  restores the old behaviour.
- **An application reading call audio slower than real time now loses the oldest audio** rather than
  receiving all of it late. `Config::inbound_queue` raises the bound and
  `MediaDiscardCounts::inbound_frames_shed` reports when it bites. A maximal concealment run is
  200 ms and can fill the default queue by itself.
- **`sipx-rtp`'s `Context::new` takes the negotiated protection profile** and `SrtpKeys` carries it.
  Code constructing either directly needs the profile threaded through.
- **An option a command does not define is a usage error (exit 2)** rather than silently discarded.
- **`--cancel-timeout` is separate from `--timeout`** on `dial`; `--mode generated-media` is explicit
  and symmetric on both load commands; `scenario` exits non-zero on a refused frame; `version --json`
  emits an object.
- The call module was split into six files and the resolver moved into `sipx-transport`. **No public
  path, name or signature moved** in the split.

## Intentional limits

- sipx is a programmable user-agent stack and diagnostic phone — not a proxy, registrar,
  configuration-driven PBX, routing product or general browser-media engine.
- **Video is not admitted.** The decision is recorded in `docs/designs/video.md` with the cost
  measured across every seam it would touch and the evidence that would reverse it. The vision's
  telephony-audio focus is unchanged.
- **No speech recognition or synthesis implementation ships.** The contract, driver and privacy
  boundary exist; nothing behind them does, and none should be inferred.
- **AEAD interoperation is proven for `AEAD_AES_256_GCM` over DTLS only.** A native browser derives
  its own session keys and agrees with sipx, and a deliberately wrong master-salt offset is proved
  to fail that run. `AEAD_AES_128_GCM` and the SDES keying path are not covered, and RFC 7714
  publishes no key-derivation vector to check them against.
- **The RFC 7092 coupling role holds two of six roles.** Reliable provisionals, PRACK and offerless
  INVITE are deliberately refused rather than half-relayed, because mapping them would mean
  describing a media endpoint this role does not have.
- **The multiplexed-offer fix has no observed browser call behind it** — it rests on a byte-pinned
  vector and the adversarial harness.
- The endpoint-load comparison covers one UDP responder signalling profile without SDP or media, and
  its intervals overlap at the tested ceiling, so it is explicitly inconclusive rather than a
  ranking.
- The published coverage figure is generated and **nothing gates on it**; the page states what the
  measurement excludes and why.
- **No independent production application or third-party security audit is recorded.** Stable
  promotion still requires use by an application nobody in this repository wrote, and repository
  checks do not manufacture that evidence.
