# sipx 1.0.0-rc.16

Five stories: the DSP graph gets processors to run, two contract events get producers, and a frame
stops printing its audio into a log. A prerelease on the same terms as its predecessors — stable
promotion still requires use by an application nobody in this repository wrote.

## Install

```sh
cargo add sipx-call@=1.0.0-rc.16
cargo install --locked --version '=1.0.0-rc.16' sipx-cli
```

## Fixed

**A call-audio frame no longer renders its samples when it is logged.** The derived `Debug` on
`sipx_audio::AnalysisFrame` printed every borrowed sample, so any `tracing` field, panic message or
test failure carrying a frame put **raw call audio** into a record whose length was the frame's — up
to 65,536 values — and it was reachable from a refusal record the call layer already writes. It now
carries direction, sequence, discontinuity and a sample *count*. The same shape on
`sipx_media::PcmFrame` is latent rather than live and is filed as `M-107`.

**`call.bridged` and `call.unbridged` have a producer.** Both were listed in the application
contract and wrote the call snapshot's `bridged` member, and nothing could emit either. The fact is
the call's own — a driver watching its own instructions cannot tell a coupling that ended because a
leg ended from one it dropped itself — so the bridge arm carries the leg name the caller supplies.

**Registry publication spends one rate-limit budget across a whole release** rather than restarting
it on every frontier rerun, and both publication workflows now state that budget themselves. An
unreadable *name* probe paces conservatively and continues where an unreadable *version* probe still
refuses, because only the second decides what is published; the specification says so now.

## Added

**Nine deterministic built-in call-DSP processors** — gain, polarity, hard and soft clipping, bit
crushing, a bounded delay/stutter line, and one-pole low-pass, high-pass and peaking filters — ship
through the *public* processor contract, with `GraphPlan::with_built_in` as the workspace registry
that lets a call-local graph run them inline.

Two things about them are worth reading before use. **Provenance is a property of the stage, not the
plan**: a built-in beside an application's processor lends that processor nothing, and the same
built-in handed to the public door is still refused. And each effect's documentation says what it
explicitly **does not** do — `soft_clip` is memoryless and never reaches full scale, so it can never
report saturation; `stutter` does not feed back; the filters offer no `Q`, order or shelving.

Conformance is reported the same way: every processor passes, and the unproven set is asserted to be
**exactly** the allocation check, which is unprovable for any processor here because `unsafe_code` is
forbidden workspace-wide and no counting allocator can be installed.

## Changed

**The contention proof has a subject that can go red.** A 200-call generated-media pair, kept out of
the ordinary suite, measured **6 of 6** failing at a responder ceiling equal to the generator's
concurrency and **0 of 6** with the headroom. The 40-call variant that was proposed for this was
built, measured at 3 of 6, and rejected — a 50% signal is a flaky gate rather than a proof. The
ceiling both load pairs use is now one derivation that subject defends.

## Intentional limits

- **No measured frequency response, CPU cost or allocation figure** for the new effects; `X-109`
  owns that. The peaking filter's `band_gain` is the scale on an extracted band, not the magnitude
  at centre, and a first-order pair does not reach unity — stated rather than implied.
- **The supervised DSP worker still runs in a thread, not its own process** (`M-102`).
- **No noise reduction ships** (`M-66`), and no application-facing control of a graph (`M-67`).
- **No speech implementation ships** behind its contract.
- **AEAD interoperation is proven for `AEAD_AES_256_GCM` over DTLS only.**
- **The browser binding has no run against a real WSS endpoint.**
- **No independent production application or third-party security audit is recorded.**

## Evidence
