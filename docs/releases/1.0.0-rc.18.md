# sipx 1.0.0-rc.18

Work from five stories, of which two close. The DSP epic's last unbuilt door — application control
of a call's graph — plus a hardening pass on what was already behind it, which found three real
defects reachable from public API. A prerelease on the same terms as its predecessors: stable
promotion still requires use by an application nobody in this repository wrote.

Three stories ship their work and stay open, each naming what it still owes. Per-processor CPU is
untaken: the harness exists and refuses to report a figure from a loaded machine, which is the
honest outcome on this box rather than a gap in the code, and two acceptance rows depend on it. The
noise reducer's activity hint is produced and measured but not yet wired through the control surface
that landed in this same candidate; that wiring is `M-119`.

## Install

```sh
cargo add sipx-call@=1.0.0-rc.18
cargo install --locked --version '=1.0.0-rc.18' sipx-cli
```

## Added

**An application can control a call's DSP graph.** The built-in registry is published —
`BuiltIn::registered()`, `from_id(id, shape)` and `parameters()` — so an SDK has a list to offer
rather than a set of names it must know. A live stage's parameters can be moved against a named
generation: validated against the declared schema off the media path, applied under the same take a
frame needs, and returning one terminal outcome. Every transition is readable, refusals included,
and a burst of parameter updates cannot push an activation out of a bounded queue.

What an application **cannot** do is stated as plainly as what it can, because a control surface's
boundary is the part that has to be argued rather than discovered. It cannot supply a processor, a
program, a callback, an execution profile, a deadline, a failure action or a graph bound — none has
a shape in the vocabulary. It cannot claim containment; that is derived from the stages and only
reported. It cannot reach another call's graph, because no verb carries a call identifier. And it
cannot reach a supervised stage's parameters, which is refused rather than dropped.

**A packaged magnitude sweep, in integer arithmetic end to end.** `sipx_audio::dsp::response` takes
a *factory* rather than a processor, so a built-in and an application-supplied processor run through
the same door. The probe is a shipped 65-entry quarter-wave table and every step is integer, so a
response is the same number on every machine, at any load, in debug and in release.

It settled two things the specs had left as names rather than numbers:

- **`cutoff_hz` is the half-power point, to the thousandth.** Both one-pole filters measure exactly
  707 — `⌊1000/√2⌉` — at 125, 250, 500, 1,000 and 2,000 Hz. The coefficient table was documented;
  where the corner actually landed was not.
- **The peaking filter's extracted band reaches 667 thousandths of unity.** So `band_gain` 4.0 peaks
  at 3,001 and 2.0 at 1,667. A cut is shallower still — 336 measured where the model says 333,
  because the band is not exactly in phase with what it is subtracted from.

Predictions were written and passing *before* any figure was read out, and the recorded figures are
named apart from them on purpose. The sweep is calibrated by a pure gain and shown catching a
nonlinearity: the same filter measures identically at amplitude 1,024 and 8,192 and differently at
16,384, where its own lift reaches the clamp.

**The noise reducer's declared input has a producer.** `ActivityHint` turns drained analysis
observations into the `voice_active` parameter the reducer's own declaration named and which nothing
in the workspace supplied. Sans-I/O: no clock, no allocation after construction, no call into either
side — every decision is a comparison between caller-supplied positions and declared counts.

## Fixed

**A DSP graph rendered raw call audio in a `Debug` record.** The same defect as rc.16's and rc.17's,
one level up: every type between the graph and the samples derived `Debug`, so the frame in flight,
the staging buffer, the 4,096-sample scratch region and up to nine more frames held by a supervised
stage were all printable. One `tracing` field, panic message or failing assertion naming a graph put
the call's audio into a record whose length was the frame's — 10,020 octets measured for a two-stage
graph.

**A renegotiation carried a graph onto audio it never agreed to.** `MediaSession::reconfigure`
re-anchored both directions and kept the chain, whatever the new `Config` said, while every stage
was prepared for one format and every buffer sized from one packetisation. Measured on a µ-law →
G.722 re-INVITE, 8 kHz/160 to 16 kHz/320: the graph stayed at generation 1 and **every subsequent
frame passed through untouched** for the rest of the call, with nothing saying so. For a stage whose
absence the spec calls a policy breach rather than a quality regression, that is unprocessed audio
leaving the stack while the graph reports itself healthy.

**Simultaneous bypasses lost all but the last transition.** One transition was carried out per
frame, so a chain whose stages spend their miss budgets on the same frame — which is what a chain of
three misbehaving workers does — journalled one of them. Bypasses are now pushed where they happen.
Two smaller gaps closed with it: the journal counted what it dropped and no caller could read the
figure, and the `Undersized` refusal was the one row of the refusal table with no test.

**An RTP packet no longer renders its payload, and an SDES item no longer renders its owner.** Two
sensitivities, deliberately kept apart. A payload is the call still encoded — for G.711 one octet
per sample — so its record now carries payload type, sequence, timestamp, SSRC, marker and lengths.
An RFC 3550 §6.5 item is not audio at all: it is a `CNAME`, `NAME`, `EMAIL`, `PHONE` or `LOC`, which
is personal data about a participant. A `CNAME` exception was argued and rejected — §6.5.1's
recommended form is `user@host` derived from a login name, the `kind` octet that would select the
exception is chosen by the far end, and the value is uncapped in memory, so the exception would need
its own truncation. Report blocks are still rendered in full, pinned by a test, so that anyone
generalising the redaction argues with a test rather than with a comment.

## Changed

**Two examples you can hear.** `call_and_listen` dials `sip:<user>@<host>` and plays the far end to
the default output device as it arrives; `softphone` adds a microphone and sends through an ordered
outbound chain assembled from the published registry. Both negotiate whatever capture format the
device actually offers instead of demanding one, and `--advertise` separates the address written into
SDP from the address the socket binds.

The troubleshooting guide gains the failure that motivated them, which no counter reports: a call
that answers and carries no audio because signalling and media took different network interfaces. A
retransmitted `200 OK` is the tell. Two neighbours get the same treatment — advertising an address
inside a private range the far end also uses, and expecting a virtual service address to be an
address at all.
