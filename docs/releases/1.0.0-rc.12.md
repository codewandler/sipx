# sipx 1.0.0-rc.12

sipx `1.0.0-rc.12` is about things that were quietly wrong rather than visibly broken: a WebSocket
frame the browser kernel truncated without saying so, a load run that under-counted every time, and
dead code no Linux gate could ever see. It is a prerelease on the same terms as its predecessors —
Supported APIs receive migration guidance when they change, Experimental APIs may change without it,
and stable promotion still requires use by an application nobody in this repository wrote.

`1.0.0-rc.10` and `1.0.0-rc.11` were cut and gated locally on the same day and are contained in this
release; the work of every candidate since `rc.2` is in the changelog.

## Install

Pin every sipx crate to the same exact release candidate:

```sh
cargo add sipx-call@=1.0.0-rc.12
```

Install the diagnostic CLI:

```sh
cargo install --locked --version '=1.0.0-rc.12' sipx-cli
```

## What changed

**The browser session kernel refuses a coalesced frame.** A WebSocket message carrying more than one
SIP message — or one message followed by any other octets — was parsed down to its first message,
acted on, and the rest discarded with nothing counted. `docs/specs/sip-tls.md` §4 requires the
connection to close. The host could not have detected this itself without parsing SIP in JavaScript,
which is the one thing the kernel exists to avoid.

**`sipx load --calls 1` reports the call it placed.** A bound cancelled the very call that reached
it, so every bounded run under-reported by one and the smallest run a user can ask for could never
report a success. Calls a bound admitted are now waited for; a process stop still ends calls in
flight at once.

**Every outbound command walks its resolved candidates the same way.** `peers` no longer gives up
after the first address, and `load` and `scenario` report `candidates_attempted` and
`candidates_resolved` when a pass fails — three of the five loops replaced counted nothing at all.

**Two RTP header-extension defects are closed.** A bridged call now forwards the extension it
received; and an extension whose length word disagrees with the bytes behind it is refused at
`Packet::encode`, because it moved the header boundary into the media — putting a run of
*unencrypted* audio on the wire on an SRTP leg, and truncating what a plain leg's peer played.

**The gate sees dead code on platforms it cannot build.** A helper gated on a feature while its only
caller was gated on the feature *and* Linux kept two CI jobs red for a day while every local check
was green. There is now a check for the shape and a cross-target build for `x86_64-pc-windows-gnu`,
established by measuring all four non-Linux targets rather than assuming.

**Two calls a host owns can be bridged, and several joined to a conference**, through the public API
— the media coupling only, with each call still owned and driven by the host.

**The custom call-DSP contract ships** with capability discovery, a caller-owned bounded workspace,
three named execution profiles and a conformance harness. **No processor implementation ships behind
it.**

**A browser WebSocket signalling binding** drives the WebAssembly kernel over WSS with bounded
queues and a reconnect budget that ends in a typed event rather than a retry loop.

## Migration

- **Six public structs became `#[non_exhaustive]`** — `sipx_media::Encoded`, `sipx_media::Config`,
  `sipx_media::browser::SelectedComponent`, `sipx_media::ice::Gathering`, `sipx_rtp::Packet` and
  `sipx_rtp::dtmf::Event`. Call `T::new(..)` and assign the rest, which stay `pub`. Taken before
  `1.0.0` because the attribute can be *removed* in a minor release and only *added* in a major one.
- **Twenty-five public enums on the media path became `#[non_exhaustive]`.** An exhaustive `match`
  needs a fallback arm; adding a variant stops being a breaking change in return.
- **`MediaDiscardCounts::srtp_protect_failures` is removed.** Read `malformed_extensions_dropped`
  instead — it counts the same caller mistake one boundary earlier. Every `protect` failure path was
  enumerated against the code before the field went.
- **`dial`'s stated deadline funds the whole command**, not each phase, so `invitation_elapsed_ms`
  is measured from the start of the deadline rather than from the INVITE.

## Intentional limits

- sipx is a programmable user-agent stack and diagnostic phone — not a proxy, registrar,
  configuration-driven PBX, routing product or general browser-media engine. Video is not admitted.
- **No speech recognition or synthesis implementation ships**, and no DSP processor ships behind the
  new contract. The contracts, drivers and privacy boundaries exist; nothing behind them does.
- **AEAD interoperation is proven for `AEAD_AES_256_GCM` over DTLS only.**
- **The RFC 7092 coupling role now relays the early negotiation carriers**, but an offerless INVITE
  whose source does not offer `100rel` is still refused: this stack implements the `2xx`/ACK carrier
  on neither side, so relaying it would have been an unproven half-delivery.
- **The browser binding has no run against a real WSS endpoint**, which needs a matched browser and
  WebDriver on a hosted runner.
- **No independent production application or third-party security audit is recorded.** Stable
  promotion still requires use by an application nobody in this repository wrote.
