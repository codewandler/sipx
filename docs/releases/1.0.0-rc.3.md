# sipx 1.0.0-rc.3

sipx `1.0.0-rc.3` is the second published release candidate for stable 1.0. It answers two
independent external sweeps of the published `1.0.0-rc.2` artifacts — each run from a fresh clone
against the released musl archive and a pinned registry install, with security explicitly excluded
from both — and lands the work those sweeps made ready. Twenty-five findings across call lifecycle,
endpoint reachability, timeout honesty, refusal signalling, automation contracts and published
onboarding are fixed, one codec and one resolver are added, and the largest module in the workspace
is split without moving a public path. It remains a prerelease on the same terms as `rc.2`.

## Install

Pin every sipx crate to the same exact release candidate:

```sh
cargo add sipx-call@=1.0.0-rc.3
```

Install the diagnostic CLI:

```sh
cargo install --locked \
  --version '=1.0.0-rc.3' \
  sipx-cli
```

The GitHub Release also carries native archives for x86-64 and Arm64 musl Linux, Intel and Arm64
macOS, and x86-64 Windows. Verify the selected archive against `SHA256SUMS`; its adjacent SPDX 2.3
document and internal `build-manifest.json` bind the dependency set, target, release commit,
toolchain and feature selection. Portable archives contain no optional native features.

For the optional browser-audio profile, install through Cargo with Opus and DTLS enabled:

```sh
cargo install --locked \
  --version '=1.0.0-rc.3' \
  --features opus,dtls \
  sipx-cli
```

## What changed after 1.0.0-rc.2

- **Every outbound command reaches a named SIP target without an external lookup.** A normative
  contract turns a `sip:`/`sips:` URI, optional explicit port and optional transport selection into
  bounded ordered candidates: NAPTR chooses the transport, SRV the host and port, A/AAAA the
  addresses, while literal IPv4 and IPv6 targets bypass even resolver setup. Calling, registration,
  bounded load, registrar-backed peer listing and scenario automation share one resolver with a
  two-second per-question and eight-second overall deadline, finite lookup, record and candidate
  limits, a bounded serial connection budget and one cross-record cache. The original hostname stays
  the TLS/WSS verification identity unless a validated server name explicitly replaces it, a `sips:`
  URI never falls back to a cleartext candidate, and "the server said no records" stays
  distinguishable from "the question could not be asked".
- **Calls negotiate and carry G.722.** The codec is native fixed-point sub-band ADPCM, built into
  every configuration with no feature gate, and verified bit-exactly against the ITU-T Appendix II
  digital test sequences from a committed corpus. RFC 3551 §4.5.2's inconsistency is structural
  rather than a special case at one call site: 16 kHz audio drives packet sizing, PCM conversion,
  capture, WAV headers, device audio and recording durations, while the RTP timestamp advances at
  8000. A bare static payload type 9 with no `a=rtpmap` is accepted, as is `9 G722/8000` and a
  dynamic number matched by its rtpmap. Preference sits below Opus and above G.711 and is stated in
  the offer/answer documentation instead of implied by list order.
- **The CLI is parsed once by a declarative typed command model.** The handwritten argument scanner,
  its hand-maintained flag registries and every production environment-argument read are gone. An
  option a command does not define is now a usage error naming the flag instead of being silently
  discarded, and non-Unicode input is refused as a usage error rather than panicking before startup.
  Command and option names, aliases, repeatability and ordering, environment fallbacks, defaults,
  help and version success, JSON/text separation and exit codes are preserved deliberately, and the
  generated CLI reference is synchronized from parser-owned help, so no second hand-written flag
  inventory remains.
- **Long-running commands survive supervisor termination, not just Ctrl-C.** Calling, answering and
  both bounded-load roles route interactive interrupt and, on Unix, SIGTERM through one cancellation
  path: admission closes first, dialog, media and transport work joins within the command's
  configured bound, and exactly one terminal record follows any earlier readiness record. The first
  signal is reported by name, a repeated supported signal cannot shorten the cleanup bound or
  duplicate the terminal report, and a clean stop exits 0. Platform support is typed rather than
  silently promised.
- **A confirmed call follows the dialog it owns, and a call returns near its configured budget.**
  Calling and answering share one inbound-dialog pump that prioritizes a queued remote BYE over
  interrupt and local completion, keeps answering crossed requests during teardown, and joins
  transport routes, dialog tasks, media and device workers to zero before emitting one terminal
  result. Previously a peer's BYE was ignored, an interrupted process emitted no terminal record,
  and reported call duration was wrong. Invitation expiry now sends CANCEL when a client transaction
  exists and reaches a finite join barrier even when neither CANCEL nor INVITE is answered, so short
  budgets are no longer overshot by an unreported cancellation tail.
- **Refusals reach the wire and name their real cause.** An initial offer outside the selected codec
  policy now receives a transaction-owned 488 and malformed SDP a 400, each with the normal To tag,
  matching transaction identifiers and Content-Length, sent before local teardown; the caller
  reports a rejection promptly instead of waiting out its whole invitation timeout. A refused
  connection is reported as a typed transport failure rather than a SIP timeout, while a
  non-answering UDP peer still follows the invitation timeout. Codec, media-security, profile, ICE
  and device selections validate their compiled capability before destination resolution, transport
  bind, file or device open and any datagram, so a build that cannot honour the request says so
  without needing the peer to answer.
- **Three media-path defects are fixed.** Negotiated RFC 4733 digits reach the automation actor as
  exactly one ordered event per digit with wire-derived duration facts, where previously the sender
  completed and the remote wait expired. A multiplexed browser offer that also carries candidates
  for the unused RTCP component is accepted: those candidates are bounded and dropped before the ICE
  agent sees them, so one socket, one nominated pair and one runtime component remain, and offers
  with no viable component-one path or no `a=rtcp-mux` stay typed refusals. A recording destination
  that cannot be created is refused at preflight through one reservation that writes and syncs a
  sibling temporary and installs it atomically, instead of being discovered after the call
  completed.
- **The automation surfaces state their contract and their output is machine-safe.** Scenario
  streams exit nonzero after any malformed frame, refused command or failed operation, flushing
  every correlated envelope and emitting one terminal completion or failure event, and the canonical
  flat frame shape is documented in parser-owned help and the public reference with a copyable
  transcript. The bounded load tools share one workload vocabulary and default to signalling on both
  sides, with generated media selected explicitly and symmetrically and incompatible explicit modes
  refused before dialog admission. Report fields are stored so a repeated key is unrepresentable,
  `version --json` emits one stable object, and progress records carry no terminal escape sequences
  unless stderr is a terminal and `NO_COLOR` is unset.
- **The call module is six modules.** Hold and resume, ICE restart, offer/answer settlement,
  transfer, re-INVITE and session timers moved into private siblings, leaving the call type and its
  lifecycle in the module root. No public path, name or signature moves: the all-features rustdoc
  item listing is byte-identical to the merge base and the whole suite passes with no edit under
  the test tree. It is a pure move with no behaviour change and no cleanup riding along.
- **Every shipped call verb has a guide with a compiled example, and onboarding is checked source.**
  Hold and resume, blind transfer, attended transfer, sending and collecting DTMF, playback,
  recording and two-leg coupling each have a site guide whose sample is inlined byte-exactly from a
  real workspace example and compiled with the workspace, and the fit list links every capability it
  claims to the guide that shows it. A registry-shaped consumer crate compiles the displayed answer
  example from exactly the displayed dependency snippet, so the snippet cannot omit a package the
  example imports.
- **Two contracts are specified ahead of the code that will implement them.** Interchangeable local
  speech providers define recognition and synthesis session contracts, a discovery descriptor,
  endpoint-default versus per-call override precedence with a typed refusal order, lifecycle events
  kept disjoint from SIP failures, and conformance vectors for both interfaces. Deterministic
  real-time call-audio analysis defines a sans-I/O frame contract whose windows and hangovers are
  sample counts derived from the declared rate, with integer predicates, typed reset versus refusal,
  explicit memory, CPU and queue bounds with a deterministic overflow marker, and sample-level
  vectors. Neither ships code, and both name the shared media attachment that later work must reuse
  instead of adding a second tap.

## Migration and stability

- **Undefined options are now usage errors:** a command that previously discarded an option it does
  not define now exits 2 and names the flag. A script that passed `register --timeout 3` ran an
  unbounded registration and received no indication the flag was ignored; that invocation now fails
  instead. Remove the flag from such calls.
- **Cancellation allowance is named separately:** `--timeout` remains the invitation-answer phase,
  and the CANCEL cleanup that follows expiry or interrupt is now `--cancel-timeout <S>`, default 2,
  where `0` performs no timed cancellation wait. A script that treated `--timeout` as the total
  process budget should now set both values.
- **Bounded load defaults to signalling on both sides:** `load` no longer starts media against a
  signalling-only responder. Select `--mode generated-media` explicitly and symmetrically on both
  commands; an incompatible explicit pair is refused before dialog admission and an invalid local
  mode is refused before any I/O.
- **Scenario streams use the flat frame shape and report failure through exit status:** the
  canonical `{"id":…,"command":…,…}` form is accepted, the nested one-key-per-command shape the
  older help implied is not, `do` remains a compatibility alias only when `command` is absent, and
  any refusal or failed operation exits 1 so a later success cannot hide it.
- **`version --json` emits JSON:** a consumer that parsed the previous plain-text output must read
  the stable object instead. Neither output form accepts a positional argument.
- **The call-module split moves nothing public:** no import, path, name or signature changes, so no
  action is required for it.
- **Supported APIs:** this candidate is not the stable API freeze. If a Supported surface changes
  before 1.0, the next changelog entry will include migration guidance.
- **Experimental APIs:** the language-neutral application contract, SIP over QUIC and other
  explicitly Experimental surfaces may change or disappear without that guide.

## Intentional limits

- sipx is a programmable user-agent stack and diagnostic phone, not a proxy, registrar,
  configuration-driven PBX, routing product or general browser-media engine.
- TURN relay, video, data channels and a browser-facing SDK are not included. The named
  browser-audio profile remains one fail-closed audio composition.
- The portable archives omit `device-audio`, `opus` and `dtls`; Cargo installation is the supported
  path for those optional native features. G.722 is not among them and is present in every build.
- The local-speech and call-audio-analysis contracts are specifications only. No implementation of
  either ships in this candidate, and neither contract should be read as an available capability.
- The comparative endpoint-load runs were re-measured for this boundary against this candidate's
  build, under the same pinned open-loop driver, host, workload, ceiling, seed and pass/fail
  contract as the retained peer evidence. The result still covers one UDP responder signalling
  profile without SDP or media and is not an overall ranking. It does not measure caller behavior,
  secure transports, connection churn, audio, proxy, registrar, routing or cluster workloads.
- The multiplexed-offer fix is proven by a byte-pinned offer vector, runtime component facts and the
  bounded browser harness. The second browser engine whose live session produced the original
  failure was not re-run against the fix, so interoperation with that engine remains an inference
  from the captured vector rather than an observed browser call.
- Named-target resolution is implemented, tested and shared by every outbound command, but the
  public CLI reference does not yet describe it; its examples still show literal addresses. Until
  that page is updated, the resolution behavior is only documented in the specification.
- Registration attempts cannot be bounded. `register` accepts no completion deadline, so a check
  against a dead or black-holing registrar still blocks for the SIP transaction timeout rather than
  a stated one. The flag that appeared to do this is now an explicit usage error rather than a
  silently ignored one, which reports the gap without closing it. A story is filed for the deadline
  itself.
- No independent production application or third-party security audit has been recorded, and both
  external sweeps excluded security by declaration. Stable promotion still requires use by an
  application nobody in this repository wrote; repository checks do not manufacture that evidence.
