# sipx 1.0.0-beta.4

sipx `1.0.0-beta.4` is a feature-and-security prerelease for programmable SIP endpoints. It adds
one bounded browser-compatible audio profile and the deployment-address controls needed by common
non-ICE networks, while tightening authenticated control traffic and hostile-input boundaries.

Pin the exact Rust crates while the API remains pre-1.0:

```bash
cargo add sipx-call@=1.0.0-beta.4
```

Install the diagnostic phone from crates.io:

```bash
cargo install sipx-cli \
  --registry crates-io \
  --version '=1.0.0-beta.4' \
  --locked
```

The named browser-audio profile is optional and needs both native media features:

```bash
cargo install sipx-cli \
  --registry crates-io \
  --version '=1.0.0-beta.4' \
  --locked \
  --features opus,dtls
```

## What changed since beta.3

- One fail-closed browser-audio policy composes authenticated WSS, one audio media section, ICE,
  DTLS-SRTP, multiplexed RTP/RTCP and Opus. Missing build features, an incompatible setup role, a
  changed fingerprint, absent nomination or weaker media produces a typed refusal instead of a
  fallback to SDES or clear RTP.
- One nominated media component owns STUN, DTLS, SRTP and SRTCP on the same bounded socket path.
  Nomination selects the DTLS peer, fingerprint verification precedes key installation, and
  cancellation joins every worker.
- The native-browser proof exercises both SIP roles and requires non-silent Opus in both
  directions. Its structured evidence cross-checks the selected candidate pair, codec, keying and
  packet counts at both ends; separate fingerprint, nomination and downgrade mutations pin the
  refusal boundaries.
- Applications can bind media locally while advertising a chosen deployment address. The CLI adds
  `--advertise`, reports both bound and advertised addresses, and preserves symmetric-RTP latching
  for the widely deployed non-ICE path.
- RTCP multiplexing and complementary DTLS setup roles now reach live calls. SRTCP has an
  independent authenticated replay window, including the 31-bit index boundary.
- Malformed SIP that cannot support a response is refused with typed errors; WebSocket assembly
  applies the SIP message ceiling before allocation; Via branches and dialog tags require a
  cryptographic random source by construction.

This beta intentionally changes two public struct-literal surfaces. `DialOptions` gains
`media_bind_address`, and `MediaPolicy` gains `profile`. Constructor and builder callers retain the
ordinary defaults; struct-literal callers must supply the new fields. Supported APIs may still
change before stable 1.0 with changelog entries and migration guidance. Experimental APIs may
change or be removed without that guide.

## Intentional omissions

- **TURN-required networks:** host and server-reflexive candidates are proven; relayed candidates
  and a TURN client are not implemented.
- **Video:** the profile carries one audio media section and no video codec or runtime.
- **Data channels:** there is no SCTP or data-channel negotiation or transport.
- **A general browser API or WebRTC engine:** sipx exposes a bounded SIP call profile and proof
  harness, not browser bindings, arbitrary media sections, trickle ICE, bundling or a browser SDK.
- **Stable `1.0` compatibility:** `1.0.0-beta.4` remains a prerelease; it is not an API freeze.

The executable `browser_audio_proof` example and the complete native-browser command are documented
on the [native-browser proof page](https://codewandler.github.io/sipx/docs/reference/browser-audio-proof).
The proof page also states the topology and evidence limits; selecting the profile alone is not an
interoperability result.

All public packages are produced from one immutable annotated tag, verified from exact registry
versions, exercised through an installed Opus CLI, and checked against documentation deployed from
the same commit. This repository prerelease is not a broader announcement.
