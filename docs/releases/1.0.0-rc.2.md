# sipx 1.0.0-rc.2

sipx `1.0.0-rc.2` is the first published release candidate for stable 1.0. It integrates the
complete post-beta.7 transport, media, signalling, observability and distribution wave as one
immutable boundary for external review. The RC.1 tag remains an immutable refused cut: its
protected gate passed, then registry rehearsal found one stale internal dependency requirement and
stopped before publishing any package, archive or release record. RC.2 fixes that manifest edge
and checks the live release graph before the protected rehearsal.

## Install

Pin every sipx crate to the same exact release candidate:

```sh
cargo add sipx-call@=1.0.0-rc.2
```

Install the diagnostic CLI:

```sh
cargo install --locked \
  --version '=1.0.0-rc.2' \
  sipx-cli
```

The GitHub Release also carries native archives for x86-64 and Arm64 musl Linux, Intel and Arm64
macOS, and x86-64 Windows. Verify the selected archive against `SHA256SUMS`; its adjacent SPDX 2.3
document and internal `build-manifest.json` bind the dependency set, target, release commit,
toolchain and feature selection. Portable archives contain no optional native features.

For the optional browser-audio profile, install through Cargo with Opus and DTLS enabled:

```sh
cargo install --locked \
  --version '=1.0.0-rc.2' \
  --features opus,dtls \
  sipx-cli
```

## What changed after beta.7

- **Transport fallback and drain are explicit.** An oversized UDP request switches to TCP at the
  same peer before transaction creation under RFC 3261's path-MTU rules. Endpoints can stop new
  dialog admission, continue established and in-dialog work, await causal completion, and report
  work terminated at a bounded deadline.
- **Observability leaves policy with the application.** Redacted signalling can be emitted from the
  existing bounded capture path as non-blocking HEP3 UDP datagrams. Per-stream RTCP loss, jitter and
  round-trip samples reach an application callback that remains attached through re-INVITE, media
  replacement and ICE restart. Collector and callback failures are isolated from calls.
- **Linear PCM and L16 have explicit formats and rates.** Applications can play unsigned 8-bit or
  signed 16-bit mono PCM and capture at a supported selected rate through one bounded streaming
  resampler. L16 negotiates static 44.1 kHz mono payload 11 and dynamic 8 kHz mono; the unsupported
  static stereo form is refused.
- **Parser-owned edits cover routing and privacy gaps.** TEL parameters are exposed as an
  allocation-free typed iterator with exact byte offsets. Address presentation and Warning agents
  can be replaced atomically without rebuilding surrounding syntax. Successfully transmitted
  application provisional responses refresh one exact server transaction's finite unanswered
  guard, so a long-ringing call remains answerable.
- **Three reproduced call and registration defects are fixed.** Bodyless re-INVITEs complete a
  delayed offer in the successful response and settle the ACK answer. Dynamic RTP payload numbers
  remain distinct by direction. One transient registration-refresh failure is retried within the
  granted lease.
- **Distribution now proves the executable on each target.** The protected workflow builds five
  native CLI archives with no optional features, completes a bounded loopback call on every target,
  validates static linkage for musl Linux, emits target-filtered SPDX documents, and refuses to
  replace different bytes on retry.
- **The endpoint responder comparison has compatible evidence on both sides.** Both retained runs
  share one host, open-loop driver, workload, ceiling, seed and pass/fail contract. Their supported
  intervals overlap at the highest tested rate, so the result is inconclusive and is not an overall
  ranking.
- **The public documentation now explains the architecture directly.** The new layering page shows
  the sans-I/O core, explicit byte and timer inputs, driver ownership, and the deterministic testing
  boundary.

## Migration and stability

- **Transport MTU configuration:** replace `Config::mtu = value` with
  `Config::path_mtu = Some(value)`. Use `None` for an unknown path MTU; sipx then applies the
  1300-byte RFC 3261 threshold. A known path uses the stated MTU with the required 200-byte
  headroom.
- **Supported APIs:** this candidate is not the stable API freeze. If a Supported surface changes
  before 1.0, the next changelog entry will include migration guidance.
- **Experimental APIs:** the language-neutral application contract, SIP over QUIC and other
  explicitly Experimental surfaces may change or disappear without that guide.

## Intentional limits

- sipx is a programmable user-agent stack and diagnostic phone, not a proxy, registrar,
  configuration-driven PBX, routing product or general browser-media engine.
- TURN relay, video, data channels and a browser-facing SDK are not included. The named
  browser-audio profile remains one fail-closed audio composition.
- The portable archives omit `device-audio`, `opus` and `dtls`; Cargo installation is the supported
  path for those optional native features.
- The comparative result covers one UDP responder signalling profile without SDP or media. It does
  not measure caller behavior, secure transports, connection churn, audio, proxy, registrar,
  routing or cluster workloads.
- No independent production application or third-party security audit has been recorded. Stable
  promotion still requires outside-use evidence; repository checks do not manufacture it.
