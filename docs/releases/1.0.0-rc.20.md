# sipx 1.0.0-rc.20

This is the first public candidate after rc.17. The rc.18 and rc.19 boundaries were prepared and
retained locally but never pushed or published; rc.20 carries their application-controlled DSP and
hardening work, then closes a five-story conformance wave under a fresh immutable tag.

Stable promotion remains deliberately out of scope. It still requires use by an application nobody
in this repository wrote.

## Install

```sh
cargo add sipx-call@=1.0.0-rc.20
cargo install --locked --version '=1.0.0-rc.20' sipx-cli
```

## The release boundary works again

The protected release workflow had a structural error with unusually poor evidence: it asked for a
runner's temporary directory while evaluating the job-level environment, before a runner existed.
The platform rejected the workflow before it created a job, leaving no step log. Every local release
check passed because those checks held what the timing file contained and where it was consumed, but
not whether the expression supplying its path was legal at that scope.

The timing path now enters only at step execution. The gate, its summary and the preserved artifact
name one runner-temporary file, and failing-first mutation tests make both properties part of the
repository's release contract. The ordinary and recovery workflows also pass an independent syntax
check before this boundary is tagged.

## Application-controlled DSP

An application can now name registered processors, construct a bounded call-local graph, change a
live stage's parameters against its generation, and read every transition. One stage can be bypassed
and restored without replacing the graph or opening a new epoch. A bypass imposed by the runtime
under the miss budget remains terminal, preventing an application from pinning a failing stage on
the media path, and a supervised stage refuses bypass because its output deliberately lags its input.

The same work packages an integer-only magnitude sweep for custom processors and fixes the contract
of the built-in filters with measured values. The noise reducer's declared activity hint also has a
sans-I/O producer, ready for the remaining control-surface wiring recorded on the board.

## Hardening findings

- A renegotiation that changed media format could leave the graph prepared for the old format and
  silently pass every later frame through. The graph now follows the negotiated format.
- Two stages bypassed in one frame could journal only the last transition. Both are now observable.
- A supervised worker could advertise a frame ceiling of four billion samples and make the runtime
  size buffers from it. Values above the contract's maximum are refused, guarded by a replayable
  corpus and a 1.2-million-execution campaign.
- A session could still derive more than 65,536 samples per frame while graph validation checked
  only the configured ceiling. A supervised graph then spawned a worker and surfaced its correct
  `Hello` refusal as `WorkerLost`. The plan now gets a typed `FrameSamplesOutOfRange` refusal before
  preparation, allocation or spawn, while the worker check stays independent defense in depth.
- The source checker that enforces diagnostic redaction stopped at the first nested test attribute,
  hiding the remainder of some large modules from every rule. It now recognizes only a top-level
  test module boundary. The wider view found and removed further raw-audio and credential-bearing
  diagnostics.
- A dialled leg that ended disappeared from control flow but remained in the authoritative snapshot.
  Applications now receive the ending and its leg-specific cause.

## Operator surface

`peers --timeout` makes the wait for a registrar's first NOTIFY controllable instead of fixed; zero
returns to Timer N. The budget includes name resolution, matching the other published deadlines.

## Evidence readers can find

The privacy and logging guides now publish the diagnostic redaction guarantee the source checker
already enforced. They distinguish raw sample buffers, encoded bytes on the relay path, bytes in the
crates where a call comes to rest, and fixed-size arrays treated as keys. They also state the other
half: protocol headers remain visible because a protocol log exists to explain routing and identity,
and counts and lengths remain because an incident still has to be diagnosable. A source-level test
binds every checked crate and scope to those pages, so the claim cannot silently lag the checker.

The architecture page now draws the DSP subsystem. `sipx-audio::dsp` owns the sans-I/O processor
contract; `sipx-media::dsp` owns live call-local graphs, execution profiles and supervised workers.
The page distinguishes the Rust custom-processor door from the narrower process contract and links
back to the normative specs instead of becoming another one.

One release-boundary test was hardened as well. The load-summary join test had once failed under a
busy gate and blamed an admitted call that went unanswered. CPU contention did not reproduce it;
deterministically claiming the just-released local port did. The test now exercises that collision,
retries setup within the existing five-attempt event bound and reports exhausted setup contention
separately from the measured outcome of a call that was actually admitted.

## Known and not fixed

The worker-protocol fuzzing vocabulary remains public API of a published crate. Its oracle must drive
the real crate-private callers, but its vocabulary can move to the test crate while one opaque entry
point stays behind. That refactor is recorded as `M-129` rather than rushed into this candidate.
