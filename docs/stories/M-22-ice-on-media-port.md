# Drive ICE on the media port

## Goal
Bind the agent to the socket the media already uses, so a nominated pair carries audio —
and so a peer that offers no ICE still gets symmetric RTP exactly as today.

## Acceptance
- [x] Host candidates from the bound `MediaPort`; server-reflexive over `sipx_transport::stun`
      against a configured STUN server; component 2 only when the control port was actually obtained.
      → `ice/gather.rs::gather`, `MediaPort::gather`; `host_candidates_come_off_the_bound_sockets`,
      `a_server_reflexive_candidate_comes_from_the_stun_server`,
      `a_silent_stun_server_still_yields_the_host_candidates`,
      `no_control_port_means_no_second_component`,
      `the_offer_carries_what_was_gathered_and_only_that`.
- [x] Checks demultiplexed by `dtls::classify` (RFC 5764 §5.1.2) on the port media uses: a check never
      reaches the jitter buffer and an RTP packet never reaches the agent.
      → `session.rs::demultiplex`, called by both receive loops;
      `a_check_and_a_media_packet_are_demultiplexed_on_one_port`.
- [x] Keepalives per §11: Binding Indication, Tr = 15 s, only on selected pairs.
      → the agent emits them; the driver arms `Timer::Keepalive` from its output and the send loop
      feeds `Input::DataSent` for media that actually went out.
      `a_selected_pair_is_kept_alive_with_a_binding_indication` asserts the indication carries no
      authentication, does carry `FINGERPRINT`, and carries nothing else. Tr stays at `Timers`'
      default of 15 s; the test shortens it, as it does Ta and Tn.
- [x] The selected pair replaces symmetric-RTP address learning for a stream that has one; a stream
      that has none keeps it. → `Inbound::symmetric` is `ice.is_none()`, read by `accept_source`;
      `Output::Selected` writes the same `remote` cell the send loop reads.
      `a_nominated_candidate_pair_carries_audio_when_the_host_candidates_cannot` (replaced) and
      `a_peer_that_offers_no_ice_keeps_symmetric_rtp` (kept).
- [x] **A peer offering no `a=candidate` gets exactly today's behaviour** — nothing offered, no checks,
      no timers, symmetric RTP. The existing media suite passing unchanged is the regression proof.
      A stack that requires ICE to place a call has regressed.
      → `MediaPort::start` passes `None` and spawns no driver. `quality`, `srtp`, `bridge`,
      `conference`, `opus` and `dtls_srtp` are **byte-identical to `main`** (`git diff main --`
      reports the added `ice.rs` and nothing else) and all pass, as does every `sipx-call` suite.
- [x] `ice-mismatch` (§5.3) reported in the answer when the offer's default destination for a
      component had no matching candidate, and RFC 3264 procedures used for that stream instead.
      → `ice/negotiate.rs::negotiate` and `Negotiation::answer_attributes`;
      `a_default_destination_no_candidate_matches_is_an_ice_mismatch`,
      `the_default_destination_matches_on_the_port_too`,
      `the_rtcp_default_is_only_checked_when_the_peer_offered_that_component`,
      `an_ice_mismatch_is_reported_and_the_stream_falls_back`.
- [x] The RFC registry gains RFC 8839 and moves RFC 8445 off `none`, with `docs/compliance.md`
      regenerated by `./scripts/rfc-report.py` in the same change.
      → both `partial`, notes naming restart (`M-23`), relayed candidates (`M-24`) and the lite
      role as missing. The three prose counts the checker names moved 69 → 70.
- [x] Failing-first test: `a_nominated_candidate_pair_carries_audio_when_the_host_candidates_cannot`
      — the test `M-16` names, and the reason this child comes after the agent rather than beside it.
      → `crates/sipx-media/tests/ice.rs`.

## Progress
- **Done, gate green (17 steps).** The driver is in `crates/sipx-media/src/ice/`: `gather.rs`
  (host and server-reflexive candidates off the bound `MediaPort`, and the local description the
  offer is written from), `negotiate.rs` (RFC 8839 §5.3's `ice-mismatch` and §6's "no candidate
  means no ICE"), and `driver.rs` (the async task that owns the sockets and the clock the agent
  does without).
- `MediaPort::gather` and `MediaPort::start_with_ice` are the two new entry points;
  `MediaPort::start` is untouched and is still the whole no-ICE path.
- **Every deadline the driver holds is an `Output::SetTimer` the agent asked for**, removed before
  the agent sees it fire and re-armed only by the agent's own next output. It feeds no input the
  agent did not ask for, which is the outside-in form of the triggered-check storm `da9d49f` fixed
  from the inside.
- **`docs/specs/ice.md` §2 was wrong and is corrected** (fourth correction in four stories):
  `DataSent { pair: PairId }` asks the driver for a value only the agent holds. The agent as merged
  takes `component`, which is what §11 needs. The mirror of `LocalBase`'s rule — the driver never
  learns what a pair is — is now written down next to it.
- Not done here and not claimed: ICE restart (`M-23`), relayed candidates (`M-24`), and wiring
  `MediaPort::gather` into `sipx-call`'s offer/answer, which is another story's area.
