# Fuzz the supervised DSP worker protocol

## Goal

Put `docs/specs/call-dsp-graph.md` §7.4's framing under a bounded fuzz campaign, so the one place in
this epic where the media process parses octets it did not write is covered the way every other
parser in this workspace is.

## Acceptance

- [x] A libFuzzer target drives §7.4's decoder over arbitrary octets in both directions —
      the runtime reading a worker's `Result`s and a worker reading the runtime's `Hello` and
      `Frame`s — with an invariant oracle rather than a "did it panic" check.
- [x] The oracle holds §7.4's own rules: a message is refused by its type and never by its length
      prefix, `Oversized` is decided from the header alone, no declared length ever sizes a buffer,
      and a refusal is terminal for the connection in both directions.
- [x] A committed seed corpus is generated by an example rather than typed, guarded by
      `scripts/check-corpus-untouched.sh`, and replayed byte for byte by a workspace test.
- [x] The target joins the CI fuzz-smoke job with the budget the other targets carry, and
      `./scripts/gate.py --check` accounts for it.
- [ ] The full gate is green.

## Progress

- **Done bar the gate row** (2026-08-10, `impl/M-122`). Four rows ticked; the fifth is the
  coordinator's wave gate. The campaign found a defect on the way in, which is recorded first
  because it is what the story was for.

  **The defect: the ceiling is a declared number too, and nothing bounded it.** §7.4 says "no
  declared length ever sizes a buffer" and the decoder honoured that against `max_samples` — but
  `max_samples` is itself declared, by the `Hello`, and on the *worker's* side the peer declaring it
  is whatever wrote to that process's standard input. Nothing checked it. A two-message stream —
  `Hello` at `max_samples = u32::MAX`, then a `Frame` declaring `0xFFFFFFFF` — made the frame limit
  saturate at `u32::MAX`, so `payload.resize(declared)` was handed four gigabytes; `worker::serve`
  had already asked for three buffers of about eight gigabytes on the strength of the same number;
  and `fill`'s "the count field and the length prefix must agree exactly" saturated with it and
  stopped deciding anything at the top of the range. Failing-first, at `c43ebde`:

  ```
  $ cargo test -p sipx-media --lib \
      dsp::wire::tests::a_ceiling_above_the_contracts_largest_frame_is_refused
  panicked at crates/sipx-media/src/dsp/wire.rs:813:79:
  refused: Some(Hello { direction: Inbound, format: StreamFormat { sample_rate: 8000,
           channels: 1 }, max_samples: 4294967295 })
  test result: FAILED. 0 passed; 1 failed
  ```

  The fix is one refusal and one clamp: a `Hello` above `MAX_FRAME_SAMPLES` is
  `Value { field: "max_samples" }`, as an undefined `direction` already was, and `ceiling()` bounds
  whatever the *caller* passes as well, so the buffer bound holds without trusting either end. It
  costs nothing real — a frame larger than that is refused by the processor contract before a stage
  is ever offered it. §7.4 gained the paragraph that says so.

  **The shape, and why it is not either of the two below.** The harness is
  `sipx_media::dsp::worker_protocol_sequence`, a public module of the crate that owns the decoder,
  and the fuzz target is thin. Neither shape this story sketched survived writing the oracle: its
  last rule — *a refusal is terminal in both directions* — is only worth asserting against the real
  callers, and both of them (`worker::serve`, `supervised::pump`) are crate-private. A driver in
  `sipx-testkit` would have had to publish `read_message`, `Incoming`, `Fault` and the three writers
  to reach a *model* of them, which is more public surface for a weaker claim. So the only
  dependency edit is `sipx-media` in `fuzz/Cargo.toml`; the workspace `Cargo.toml` is untouched and
  `fuzz/Cargo.lock` is gitignored, so no lockfile moved.

  **The oracle, and the evidence it is not vacuous.** Five invariants: the refusal §7.4's table
  gives for the header octets, derived independently and compared to the decoder's; a
  header-decided refusal that read a payload octet; a buffer or a ceiling grown past the contract;
  an accepted message whose samples do not account for its length; and a real caller that carried on
  past a refusal. Each was proved live by mutating the decoder and watching both the corpus replay
  and the sweep go red — the reserved-octet check deleted (caught at sweep iteration 0), `Oversized`
  moved after the payload read (`PayloadReadBeforeRefusal`, read 23 of 8 octets), the worker's read
  loop made to continue past a refusal (`read 2539 octets past a refusal that ended at 28`), and the
  pump's refused answer downgraded from `Failed` to `Withheld` (`offered 5 frames past the refusal
  at message 0`). `worker::serve`'s terminality is measured in octets; the pump's cannot be, because
  it reads through a `BufReader` whose appetite is not the protocol's, so that side is measured in
  frames offered and answers recorded instead.

  40 seeds, one refusal each and last — a seed with two only ever exercises the first, and
  `no_seed_hides_a_refusal_behind_another` enforces that. `Version` is the one table row no seed
  reaches, deliberately: the encoder writes this runtime's own version and a program that could
  rewrite one octet would be a program about one octet. The fuzzer reaches it by mutation and
  `wire`'s unit test asserts it.

  Local evidence: `cargo test -p sipx-media --all-features` green; `cargo clippy -p sipx-media
  --all-features --all-targets` clean; two campaigns with no finding — 657,132 executions in 90 s
  from the committed seeds, then 1,227,386 in 241 s from the corpus the first left behind;
  `./scripts/gate.py --check` reports 51 steps over 24 CI jobs, none unaccounted for.

- Backlog. Filed by `M-68`, which could not do this inside its own fence. The decoder is
  `sipx_media::dsp::wire`, crate-private, and `fuzz/` depends on `sipx-sip` and `sipx-testkit` and
  neither reaches it. Registering the target therefore means adding `sipx-media` to a dependency
  list — `fuzz/Cargo.toml`'s, or `sipx-testkit`'s so the driver can live beside `M-61`'s the way
  that story's does — which is a manifest and lockfile edit an implementor may not make.

  Two shapes are open and the first is probably right. **A driver in `sipx-testkit`**, following
  `M-61`'s `call_audio_sequence` exactly: the fuzz target stays thin, the oracle is shared with a
  workspace test, and a crashing corpus entry is replayed by that test byte for byte. It needs
  `sipx-media` in `sipx-testkit`'s dependencies and a public door onto the decoder. **Or a public
  `serve_worker` variant** taking arbitrary streams instead of this process's standard input and
  output, which an application would want anyway for testing its own worker without spawning it,
  and which reaches the whole decoder because both directions share `read_message`.

  `M-68` covered what it could reach without that: §7.4's refusal table has unit coverage in
  `crates/sipx-media/src/dsp/wire.rs`, and `GRAPH-19`'s header-alone `Oversized` decision is
  asserted there. That is a table walked deliberately, not a campaign.
