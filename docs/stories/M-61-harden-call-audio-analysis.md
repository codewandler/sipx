# Harden call-audio analysis against adversarial input

## Goal

Prove that untrusted call audio and hostile lifecycle sequences cannot panic, consume unbounded
resources, starve the media path or leak observations between calls.

## Acceptance

- [x] Fuzz/property targets cover every supported PCM format with extreme amplitudes, impulses, DC,
      alternating samples, arbitrary chunking, sequence gaps and format changes.
- [x] Memory and work remain within the M-57 bounds for long silence, permanent activity and event
      consumer backpressure; no network input reaches panic or unsafe code.
- [x] Cancellation races with frame delivery, reset and event backpressure leave no processor state,
      task or retained raw audio after the call's completion observation.
- [x] A concurrent-call test uses distinct sentinel streams and proves no state, metric or event can
      cross call boundaries.
- [x] Ordinary diagnostics contain algorithm/profile identity and counters but no raw audio, and any
      explicit capture facility remains outside this epic.
- [x] The adversarial corpus joins the bounded fuzz campaign and the full gate is green.

- 2026-08-09: implemented on `impl/M-61`.

  **The instrument.** `sipx_testkit::call_audio_sequence` decodes a byte string into a program over
  the analyser's whole input vocabulary — frames of hostile audio in every supported `PcmFormat`,
  declared format changes, requested resets, unflagged sequence gaps, replayed sequences and a
  consumer that stops draining — and drives it through two lanes with an invariant oracle rather
  than a "did it panic" check. `fuzz/fuzz_targets/call_audio_sequence.rs` is the thin part that
  turns a finding into a crash libFuzzer can minimise; the 20 committed seeds under
  `crates/sipx-testkit/corpus/call-audio-sequences/` are generated by
  `cargo run -p sipx-testkit --example dump_call_audio_sequences -- --write`.

  The two lanes are `docs/specs/call-audio-processing.md` §12.11's own claim: a *subject* carrying
  §12.12's `K8` calibration behind a four-slot queue, and a *reference* fixed at the subject's
  `floor_amplitude` behind a 4,096-slot one. Positions are only ever checked on the reference,
  because §8.3 may have folded the `Reset` that opened an epoch into a counted marker and an oracle
  that guessed the epoch would report its own defect. §12.11's first clause needs no lane at all —
  a window called `active` must satisfy the activation predicate at the floor, which is decidable
  from the accumulators the window already publishes.

  **Failing-first.** `a_frame_diagnostic_carries_counters_and_no_raw_audio` in
  `crates/sipx-audio/tests/call_audio_adversarial.rs`, at merge base `465605d`:

  ```
  $ cargo test -p sipx-audio --test call_audio_adversarial
  test a_frame_diagnostic_carries_counters_and_no_raw_audio ... FAILED
  a frame's diagnostic rendering carries no sample value: AnalysisFrame { direction: Inbound,
  sequence: 7, discontinuity: None, samples: [30011, 30011, 30011, … ×160 ] }
  ```

  **What the hardening found, as opposed to what it now guards.** One real defect:
  `AnalysisFrame`'s derived `Debug` rendered every borrowed sample, so any `tracing` field, panic
  message or test failure carrying a frame put raw call audio into a record whose *length was the
  frame's* — up to 65,536 values. Both halves of this story's fifth row at once, and it was
  reachable from `sipx-call`'s own refusal record. `Debug` is now hand-written and reports
  direction, sequence, declared break and the sample **count**; `EffectiveThresholds` gained a
  `Display` that is the profile identity and counters an ordinary record needs beside it, and
  `audio_feed.rs`'s two records now carry both.

  Everything else the oracle raised was the oracle's own: an epoch mis-attributed across §8.3's
  coalescing, a window attributed to the width in force at drain time rather than at completion,
  and a source count treated as a frame length across a rate change. Each is fixed in the harness
  and commented at the site, because each is a shape an oracle can get wrong twice. **No panic, no
  unbounded growth and no cross-call leak was found in the shipped analysis path** — the bounds
  §8.1, §8.2 and §8.3 declare held under every program tried.

  **Coverage.** `crates/sipx-audio/tests/call_audio_adversarial.rs` (12): the diagnostics sweep,
  §8.3's queue bound under 2,000 frames of silence and of permanent activity at three depths, §8.2's
  per-frame work bound over 3,000 frames, the silence timer firing exactly once, refusals moving
  nothing (frames and formats), arbitrary chunking producing byte-identical observations, every
  `(rate, encoding)` the boundary supports, the widest window of extremes under the widest
  calibration, and a break on every frame for 1,000 frames.
  `crates/sipx-testkit/tests/call_audio_sequences.rs` (8): corpus-equals-seeds, every committed file
  runs, decoder totality, round-trips, and a 2,000-iteration deterministic sweep over ~49,000
  generated events.
  `crates/sipx-call/tests/voice_activity_hardening.rs` (2): the cancellation race and the
  concurrent-call sentinels.

  **The sentinels are swap-sensitive, and that was checked by swapping them.** `ALPHA` transmits
  alternating ±30,011 and `BETA` ±701, both on the **outbound** tap — which the seam takes before
  encoding, so the codec never touches the numbers. Peak, RMS and deviation are each exactly the
  amplitude; 30,011 is active by a factor of fifteen and clips nothing, 701 is above the 64 silence
  floor and below `BETA`'s own 1,024 activation amplitude. Three independent dimensions are
  asserted — the metrics, the events (voice opens on `ALPHA`, never on `BETA`) and the state (each
  call's `voice_thresholds` reports its own window, activation amplitude and calibration floor,
  which the two profiles deliberately do not share). Exchanging the two clips fails on the first
  report: `left: 701, right: 30011`.

  **Cancellation.** `cancelling_detection_while_frames_are_in_flight_leaves_no_state_task_or_audio`
  replaces detection five times while a 40-packet clip is in flight and the application has read
  nothing at all, then hangs up. It runs on tokio's current-thread runtime deliberately: a watcher
  still looping over a stopped session — `M-93`'s shape, where a long-running wait answers without
  suspending — would own the only worker there is, and the `yield_now` probe after teardown would
  never resolve. After the call's completion observation: the seam refuses a new attachment
  (`SessionStopped`), `Ended` is last, no voice is left latched, no event's rendering carries a
  sample, and the analyser's snapshot shows the terminal reset's state (§12.8) rather than a stale
  period.

  **Registration.** `fuzz/Cargo.toml` gains the `[[bin]]`; `.github/workflows/ci.yml`'s `fuzz smoke`
  job gains a "Fuzz the call-audio analyser" step with the transaction driver's budget
  (`-max_total_time=60 -max_len=512`) and the committed corpus passed *second*, read-only;
  `scripts/check-corpus-untouched.sh` guards the new directory as it guards the transaction one.
  `./scripts/gate.py --check` is green: 50 steps over 23 CI jobs, none unaccounted for.

  **The gate row is left unticked deliberately.** The full `./scripts/gate.py` is the integrator's
  to run, and the campaign step itself is CI-only (`gate.py`'s `NOT_RUN_LOCALLY` names `fuzz`). A
  30-second local campaign was run against the committed corpus on the nightly toolchain and is
  recorded in the handoff; it is evidence that the target builds and starts from real seeds, not a
  substitute for the campaign.
