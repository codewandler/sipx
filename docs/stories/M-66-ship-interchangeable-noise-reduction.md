# Ship interchangeable local noise reduction

## Goal

Reduce stationary/background noise through a replaceable processor contract with honest latency,
resource and speech-damage measurements.

## Acceptance

- [x] A noise-reduction capability reports supported rates/channels, frame requirements, warm-up,
      algorithmic latency, tail, CPU/device support and whether it consumes optional VAD input.
- [x] sipx ships a local baseline implementation while an external fixture implements the same
      processor contract and passes the same lifecycle/conformance tests.
- [x] Adaptive state is bounded and isolated per call/direction; resets, discontinuities and noise
      profile changes are deterministic and never retain raw audio after teardown.
- [x] Unsupported formats/devices or an unmet real-time profile produce typed refusal/bypass; no
      silent resampling, quality change, remote processing or model download occurs.
- [ ] A predeclared corpus measures noise attenuation, speech distortion, onset recovery, latency,
      CPU and memory across silence, stationary noise, transient noise and overlapping speech.
- [ ] SDK events and docs distinguish noise reduction from VAD, echo cancellation and recognition,
      and the full gate is green.

## Progress

- Backlog. Depends on M-63; VAD input is optional after M-58.

### 2026-08-09 — implemented

Spec first: `docs/specs/call-dsp-noise-reduction.md`, normative, inheriting `M-63`'s contract,
`M-65`'s arithmetic and `M-64`'s graph rather than restating any of them.

**The interface is the deliverable.** `sipx_audio::dsp::noise` ships `NoiseReducer: FrameProcessor`
— one added method — plus a `NoiseReduction` declaration carrying the three facts `DspCapability`
cannot answer: `warm_up_positions`, `ActivityInput` (whether a VAD hint is consumed, and through
which declared flag) and `HostRequirement` (what the machine must provide, declared and never
probed). `validate()` refuses an activity claim the parameter schema does not back, so "consumes
optional VAD input" is checkable rather than prose.

**One implementation behind it, and a second beside it.** `SubbandSuppressor` (`sipx.subband_suppressor`)
is a three-band statistical suppressor built from `M-65`'s one-pole section and integer arithmetic:
`b₀ + b₁ + b₂ = x` exactly, a Q8 magnitude follower, a recursive-minimum floor with an upward creep,
and a per-band gain of `1000 − over_subtraction·floor/envelope` clamped into `min_band_gain..=1000`
and slewed. `crates/sipx-audio/tests/dsp_noise_reduction.rs` carries a **second** reducer written
from outside the crate with different arithmetic, rates, channels, warm-up, reset behaviour and
execution profile; one generic driver and one `dyn NoiseReducer` list run both.

**Substitution is proved at the call layer, not asserted.**
`crates/sipx-media/tests/dsp_noise_reduction.rs` attaches either reducer through one `carried()`
driver that names only `GraphPlan`; the activation transitions are identical and the audio is not.
`BuiltIn::SubbandSuppressor` grants the baseline `ProvenInline`; the same type built by hand at the
public door is still refused `ProfileNotAdmissible`.

**Conformance.** Both reducers pass `DSP-K1`..`DSP-K12` with the unproven set asserted to be
**exactly `DSP-K9`** — the heap component of a processor's own state, unprovable because
`unsafe_code` is forbidden workspace-wide, per `call-dsp-effects.md` §9.1. Nothing else is unproven.

**What the suppressor does and does not do** is `docs/specs/call-dsp-noise-reduction.md` §5.6 and
the type's own rustdoc, both normative: what it removes (stationary noise below the speech above
it), what it damages (the whole of any suppressed band — chest on a low voice, fricatives up top,
every onset smeared by the slew, a moving stereo image), and the five conditions under which it
makes speech *worse* (speech below the floor, non-stationary noise, overlapping speech, a
restarting epoch, a wrong hint). No dB figure is claimed beyond the one `min_band_gain` bounds it to.

Rows 1–4 are ticked. Two are not:

- **Row 5** — the corpus exists (`docs/specs/call-dsp-noise-reduction.md` §8: silence, stationary,
  transient and overlapping speech, generated by stated integer recurrences) and its attenuation,
  distortion and onset-recovery figures are asserted exactly. **CPU and memory are `X-109`'s** and
  are deliberately not invented here, so the row stays unticked until that story lands.
- **Row 6** — the docs half is done, in the spec, in `sipx_audio::dsp::noise`, in
  `sipx_media::dsp` and in `sipx-media`'s stability section (whose claim that no reducer ships was
  stale from `M-65` and is now correct). **SDK events are `M-67`'s** — there is no SDK surface to
  carry them yet — and the full gate is the integrator's to run.
