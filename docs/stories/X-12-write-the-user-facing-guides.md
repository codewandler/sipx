# Write the user-facing guides

## Goal
The pages someone actually needs: what sipx is for, what it can and cannot do yet, and how to
use it for the two or three things people will want first.

## Acceptance
- [ ] A "does this fit" page: what sipx is, what it is not, and the honest state of it —
      including that media is not encrypted yet.
- [ ] A page per thing someone would arrive wanting: place a call, answer one, register against
      a PBX, use it as a library.
- [ ] Every code sample compiles, checked in CI. A sample that has rotted is worse than none,
      because it is trusted.
- [ ] The compliance table is linked from wherever a capability is claimed, so a claim can be
      checked rather than believed.
